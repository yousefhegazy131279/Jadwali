## ما تعنيه الأرقام

- الإنجازات والسلسلة تأتي من سجل الجلسات المحفوظة، مع احتساب الجلسة مرة واحدة.
- يُحسب اليوم بحسب المنطقة الزمنية في إعدادات التذكير، ويبدأ أسبوع التقرير يوم الاثنين.
- نسبة إنجاز المهام في التقرير تعكس الحالة الحالية لمهام جداول ذلك الأسبوع؛ ليست لقطة تاريخية غير قابلة للتغيير.
- أيام التحدي موحدة بتوقيت UTC لكل المشاركين. لا تُحتسب جلسات قبل الانضمام.
- الغرفة تتحقق من موعد نهاية الجولة وسبق انضمام العضو. يجب حفظ الجلسة عند اكتمالها. العضوية لا تثبت وجود المستخدم أمام الشاشة أو اتصاله المستمر.
- في الغرفة وحدها يبدأ المضيف الجولة. حذف الغرفة يحذف المحادثة والعضوية ويحفظ رصيد الجلسات المسجلة.

## حدود العمل دون اتصال

يعمل عرض البيانات والصفحات التي حُمّلت مسبقًا، وتحرير الملاحظات، ومسودة المخطط، واستكمال مؤقت جلسة محمّلة. تُرسل العمليات بالترتيب عند الاتصال بالحساب نفسه. لا توضع مفاتيح أو رموز دخول في قاعدة الكاش الخاصة بالتطبيق.

إنشاء جدول سحابي، الذكاء الاصطناعي، الدعوات، والدردشة تتطلب الاتصال. عند تعارض تعديل ملاحظة لا يُستبدل نص جهاز آخر تلقائيًا؛ يستطيع المستخدم الاحتفاظ بنسخته كملاحظة جديدة أو تجاهل العملية بعد مراجعتها. يمكن تنزيل نسخة محلية قبل مسح الكاش. أول زيارة دون إنترنت لا تستطيع تحميل صفحة لم تُزر سابقًا.

العمل دون اتصال ليس بديلًا عن تسجيل الدخول، ولا يتجاوز صلاحيات الخادم. الصفحات الإدارية وواجهات المصادقة وملفات الحساب لا تدخل كاش استجابات البيانات. مفتاح كل نسخة شخصية يتضمن معرف الحساب، ويُرفض ربط استجابة بتوكن حساب مختلف أثناء انتقال المصادقة.

## قاعدة البيانات الإنتاجية

المشروع الذي جرى التحقق منه: `aoaacxylmuzkdgwaufmc`، الاسم `jadwali`. لم تُستخدم مشاريع حسابات Supabase الأخرى المتصلة بالأداة.

طُبق الترحيلان عبر SQL Editor بعد موافقة المستخدم:

1. `20261019033549_productivity_v2_foundation.sql`
2. `20261019040249_productivity_v2_scheduler.sql`

قراءة الإنتاج بعد التنفيذ: 14 إنجازًا، 4 قوالب، RLS مفعّل لكل جداول الميزات المتحقق منها، المستخدم لا يملك تحديث عمود معرف الإنجاز، ومهمتا Cron نشطتان. لم تُحذف جداول المستخدمين أو مهامهم أو ملفاتهم الشخصية.

استُخدمت صلاحيات أعمدة صريحة لإقرار قراءة الإشعارات والاحتفال فقط؛ تمت إزالة صلاحيات ALL الافتراضية التي قد يضيفها Supabase. الجداول الداخلية الخاصة بإيصالات الطلبات محمية أيضًا ولا تُعرض للعملاء.

ملاحظة تشغيلية: التنفيذ في SQL Editor لا يضمن تسجيل هذه النسخ في سجل Supabase CLI. لا تشغّل `db push` على جميع الملفات القديمة تلقائيًا قبل مطابقة سجل الترحيلات مع حالة قاعدة الإنتاج.

## Push والجدولة

العامل: `supabase/functions/dispatch-reminders/index.ts`، مستقل عن Jadwool؛ لا يغير وظيفة توليد الجداول أو مفاتيحها.

- استدعاء العامل POST فقط؛ يتحقق من `x-jadwali-cron-secret` بمقارنة ثابتة بعد SHA-256.
- `CRON_SECRET` لا يقل عن 32 حرفًا. رمز JWT العام ليس وسيلة تشغيل العامل.
- مفاتيح VAPID مخصصة لإشعارات المتصفح. القيم الخاصة محفوظة في Secrets/Vault ولا تدخل Git أو التقرير.
- كل 5 دقائق تعمل مهمة داخلية لإنشاء الإشعارات، ومهمة نقل لاستدعاء العامل. التوقيت تقريبي وقد يتأخر دقائق بسبب الجدولة أو خدمة الجهاز.
- اشتراك Push اختياري ولكل جهاز. iPhone/iPad قد يحتاج تثبيت الموقع على الشاشة الرئيسية.
- تُحذف اشتراكات الأجهزة المنتهية، وتوجد حدود للمحاولات ومدة حجز للطلبات لمنع تشغيلين متزامنين من معالجة الصف نفسه.
- إرسال العامل بنجاح إلى خدمة المتصفح لا يضمن ظهور التنبيه على جهاز مغلق أو في وضع عدم الإزعاج.
- إعدادات البريد غير مفعلة.

## الاختبارات

نجح آخر تشغيل في **19 اختبارًا**، يشمل اختبارات الإصدار السابق، صحة مخطط AI، سجل الجلسات، توقيت الصلوات، عزل الكاش بالحساب، التعارضات، منع تزوير الإنجاز، القوالب السبعة كمعاملة واحدة، خصوصية التحدي، أهلية الغرفة وموعد النهاية وعدم التكرار، التقارير، والتحقق من صلاحيات Anonymous ومهام الإشعارات.

نجح TypeScript. نجح بناء Next.js بـ27 صفحة ومسارات API الجديدة. نجح ESLint للملفات الجديدة دون أخطاء أو تحذيرات. يلزم إعادة هذه الفحوص إذا تغيرت الشفرة بعد هذا التوثيق.

تم قياس حوار الملاحظة على عرض هاتف 390 بكسل: الحدود الأفقية 15.6–374.4 بكسل، والعمودية 50.6–793.4 ضمن ارتفاع 844 بكسل، دون تجاوز أفقي.

اختبارات المتصفح المحلية تمت على قاعدة PGlite معزولة، بلا رسائل لمستخدمين حقيقيين: إنشاء وربط ملاحظة، إنشاء خطة أسبوع امتحانات، إنشاء تحدٍ، بدء جولة جماعية دقيقة واحدة، حفظ رصيدها وظهور إنجاز البداية، البحث السريع، والتركيز العميق. هذه الاختبارات لا تُعد إثباتًا لدخول حسابات الإنتاج أو استقبال Push على جهاز حقيقي.

## ملفات الاستلام المهمة

- `src/components/v2/`: واجهات الإصدار.
- `src/context/ProductivityContext.tsx`: التقدم والاحتفالات ومزامنة قائمة الانتظار.
- `src/lib/offline.ts`: IndexedDB وعزل الحساب والكاش.
- `src/lib/productivity.ts`: الأنواع والمساعدات.
- `src/lib/notificationDelivery.ts`: بديل عامل Vercel وقناة البريد المستقبلية غير المفعلة.
- `src/app/api/notifications/`: الإعداد العام والاشتراك الآمن للأجهزة.
- `public/sw.js`: شِل PWA وكاش الصفحات وPush.
- `supabase/migrations/20261019*`: أساس الميزات وجدولة الإنتاج.
- `tests/v2.test.cjs` و`tests/offline.test.cjs`: اختبارات العزل والتعاملات.
- `scripts/generate-notification-keys.cjs`: يولّد ملف مفاتيح محليًا، لا يعرضها ولا يستبدل ملفًا موجودًا.

لا تضف `.env.notifications.local` أو `.env.local` إلى Git أو أرشيف تسليم عام. لا تغيّر مفاتيح Groq/Jadwool أثناء إعداد Push.

## حالة النشر الأخيرة

- قاعدة الإنتاج: تم الترحيل والتحقق كما أعلاه.
- عامل Push ومفاتيحه: منشور؛ نجح الطلب المصرّح بـ200، ورُفض الطلب دون الرمز بـ401. أكد العامل جاهزية VAPID، ولم يرسل أي إشعارات أثناء اختبار التهيئة.
- واجهة Vercel: جارٍ الإعداد للنشر.
- البريد: مؤجل بطلب المستخدم.
- استقبال Push فعلي على جهاز المستخدم: يحتاج اشتراكًا وإذنًا صريحًا من الجهاز؛ لا يُدّعى نجاحه قبل اختباره.
